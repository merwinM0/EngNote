# EngNote 英文阅读助手

一个基于 **HTML + TypeScript + CSS** 的英文阅读网页应用。用户通过单一「Paste text / Edit page」入口粘贴、编辑正文或导入 Word，正文重新排版后按每页最多 3000 字符展示；支持调用 DeepSeek API 进行「AI 整理」排版与「AI 翻译」单词注释；支持按每条释义当前显示的语言导出纯白 **Word（.docx）** 文档；可将内容**保存到 SQLite 数据库**并通过顶栏的收藏白板读取，保存时可留空标题由 AI 概括；支持**邮箱注册/登录**（带验证码）。

## 快速启动（源码脚本模式）

```bash
cd EngNote
bun install --frozen-lockfile
cp .env.example .env   # 已有 .env 请保留，不要覆盖
bun dev
```

打开 `http://localhost:3000`（`bun dev` 的默认端口）。已验证 Bun **1.3.14**。无需编译可执行文件，也不再依赖 `public/dist/app.js`：Bun 原生 HTML 入口负责前端 TS / CSS 打包与开发热更新，服务端修改由 `--watch` 重启。

- `bun start`：生产模式直接运行源码（关闭 HMR），仍需保留源码、依赖与静态资源；生产认证需要 Redis、SMTP。
- `bun run typecheck`：分别检查前后端类型；`bun test`：运行文本规则、分页边界、实时编辑、Word 解压限制、接口与数据库迁移测试。
- `bun run build`：可选，仅导出前端到 `dist/` 用于检查，不是可单独部署的完整应用；SQLite / 登录仍需 Bun 后端。
- 默认绑定 `0.0.0.0`，启动时输出本机及局域网地址；本地同一局域网设备可用 `http://本机局域网IP:3000` 访问（需放行防火墙端口）。未设置 `PORT` 时，`bun dev` 使用 3000，`bun start`（生产）使用 80；如需仅本机访问，设 `HOST=127.0.0.1`。粘贴统一使用页内输入区和 Ctrl/Cmd+V，不请求剪贴板权限，也不会由 Paste 按钮触发浏览器“粘贴（P）”菜单。
- 原 `Engreading` / `index.js.map` 不再使用，也不会自动删除；现有 `.env` 与 `data.db` 保留。

### 代码逻辑与本次调整

`index.ts` 管理启动和退出 → `backend/server.ts` 初始化 SQLite、挂载两页 HTML、校验 API → `backend/auth.ts` / `redis.ts` / `mail.ts` 处理登录、验证码和会话。前端 `main.ts` 装配事件，`state.ts` 管理段落与选词，`db.ts` 管理保存/列表，`format.ts` 与 `translate.ts` 调用 DeepSeek。新增 `pagination.ts` 管理无损正文与分页，`editor.ts` 处理导入、实时编辑和草稿，`panels.ts` 管理文章内面板，`notes.ts` 管理保存 / 收藏 / 确认 / API / 账号弹窗的叠放、焦点与关闭行为，`articleTitle.ts` 管理 AI 标题总结、格式兼容与一次短标题修正，`collectionCanvas.ts` / `boardGeometry.ts` 管理收藏画布与可测试的缩放几何，`word.ts` 在浏览器提取 Word 正文，`definitionViews.ts` / `definitionLanguage.ts` 管理每条释义的独立中英文显示及缓存，`dictionary.ts` 校验单次 AI 请求同时返回的中英文释义，`dictionaryCache.ts` / `dictionaryLookup.ts` 管理有界查询缓存与本地优先的缺失词条解析，`deepseekClient.ts` / `aiUsage.ts` 封装请求预算、截断处理与用量统计。

- 修复全局正则反复校验不稳定、粘贴丢失数字、标点也被选中、跨段落合并短语等问题。
- AI 期间锁定冲突操作，使用页面版本及请求序号防止过期结果覆盖新内容；加载/失败标记不写入文章。先排版后注释，避免 AI 排版移动已有释义。
- 仅导入与编辑保留页内面板；保存、删除、未保存确认、收藏、AI 设置和账号使用原生 `<dialog>` 浮层，不替换正文或编辑区。收藏白板支持叠放确认便签；弹窗支持点击遮罩和 Esc，Tab 在当前弹窗内循环，关闭后恢复原焦点及编辑光标；不使用 `window.confirm` 或离页原生确认。
- 工作记录自动保存在当前标签页的 sessionStorage，保留全部分页、当前位置、已保存文章 ID 和未保存修改。刷新或从首页「Open your notebook」返回时，会向服务器重新确认文章及当前账户权限；自己的文章继续使用 Save changes 更新原记录，不生成同内容副本。新文章和访客草稿仍使用 Save article，其他作者的文章只能另存副本。浏览器禁止存储时会提示，关闭标签页会失去临时记录。
- 文章关联确认失败时保留正文并显示 Retry saved article，避免网络故障导致误存副本；原记录已删除时保留为未保存草稿。旧版工作记录不包含文章 ID，无法安全判断来源，仍作为草稿恢复；从收藏重新打开原文章一次即可建立关联。
- 会话改为 HttpOnly / SameSite Cookie，不再在 localStorage 保存 Token；API Key 从 Cookie 迁移为当前标签页的 sessionStorage，并可随时清除。
- 文章仍是**公开阅读书架**，不是私密笔记；只有作者可更新/删除。旧表自动追加 `owner_email`，历史文章不猜测作者，保留公开只读，可另存为自己的副本。API 不公开作者邮箱。
- 静态资源通过 HTML 入口与明确白名单提供，不再拼接任意文件路径；接口校验 JSON 类型、长度、方法与请求来源。
- 首页三张胶带便签，阅读页为笔记纸；`public/css/tokens.css` 统一水灰中性色，`public/css/tape.css` 提供不同颜色、半透明撕边的胶带按钮。按钮装饰与焦点轮廓分离，键盘和触摸操作不受剪裁影响。
- 首页与阅读页的顶栏、工具栏保持全宽及响应式边距；首页标题为 “Read English your way”，介绍英文优先、按需查看中文的阅读方式，不再保留首页页尾；阅读页移除宣传大标题，直接显示工具栏与文章。阅读纸面与分页区占主区域 80% 并居中，700px 及以下恢复可用全宽，避免小屏正文过窄。
- 首页语言按钮右侧新增「amnual / 使用指南」，通过五步简版窗口模拟阅读与 AI 设置，支持上一步 / 下一步，界面语言跟随首页切换。
- 顶栏保留 Logo、Saved articles、AI setup 和 Login / Account；正文不再保留收藏侧栏。Saved articles 打开微倾斜白板，保留两侧粘住白板的胶带，不恢复线稿或装饰文案；文章为紧凑的透明胶带按钮，作者的删除按钮位于胶带右上角。白板采用可拖动、缩放的二维画布，文章再多也不产生上下滚动的列表。密钥输入区保留 SVG 铅笔横线与手写风排版。
- 文章工具固定两行：第一行 Read、Paste text / Edit page、Import Word、Tidy this page；第二行 Add definitions、Remove a note、Save article、Export Word、Clear。Read 紧挨编辑按钮左侧，不再有单独的阅读标签行；选词时 Define selected 与 Refresh selected 加入第一行，仍保持两行。
- 取消重复的 Add text / Edit page 标签和两枚独立工具按钮，只保留一个正文入口：无正文时显示 Paste text，有正文时显示 Edit page，共用一个文本编辑区。
- `public/icons/reading-sketch.svg` 与 `pencil-line.svg` 均为本地线稿，无外部字体或 UI 框架。首页和阅读页使用 `public/icons/favicon.svg` 作为浏览器标签页图标，复用站点的青色书本 Logo，由 Bun HTML 入口统一打包。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 前端 | HTML5 + TypeScript + CSS |
| 构建/运行 | Bun（`bun dev` 启动源码与开发热更新） |
| AI 能力 | DeepSeek API（OpenAI 兼容接口） |
| 存储 | SQLite（Bun 内置 `bun:sqlite`，本地 `data.db`） |
| 密码哈希 | **慢哈希**：`argon2id`（内存/时间硬度高），经 Bun `Bun.password` 加密 |
| 验证码存储 | Redis（`redis` npm 包；不可用时降级为内存）|
| 邮件发送 | Nodemailer + SMTP，通过 `.env` 配置发信账号 |
| 依赖 | `redis`、`nodemailer`、`fflate`（本地解压 .docx） |

## 功能需求

### 界面语言（English / 中文）
- 首页与阅读页顶栏提供语言按钮：英文界面显示「中文」，中文界面显示「EN」，点击或 Tab + Enter / Space 即刻切换。首次访问默认英文，不随浏览器语言自动改成中文。
- 界面语言以 `er_ui_language_v1` 保存在本浏览器的 localStorage，首页、阅读页及同源标签页共用，刷新后恢复选择；浏览器存储被禁用时仍可在当前页面切换，刷新后回到英文。
- 切换覆盖首页文案、工具栏、分页与词数、背景选项、弹窗、表单校验、进度、常见接口错误及 AI 用量提示；已显示的提示也同步更新。不刷新页面、不重发接口或 AI 请求，不中断进行中的任务。
- **界面语言与释义语言独立**：不翻译或改写文章正文、保存的标题、输入框内容，不改变阅读页码、选词、工作草稿、API key、AI setup 的 Zh / Eng 默认释义偏好或每条批注的显示语言。切换界面不会造成未保存修改。
- `public/ts/i18n.ts` 统一维护双语文案、语言偏好和可更新的提示；`home.ts` 初始化首页，阅读页由 `main.ts` 初始化。仅翻译明确标记的界面节点，文章始终保留原文。

### 首页使用指南
- 点击语言按钮右侧的「amnual」（中文界面为「使用指南」）打开原生弹窗，按「上一步 / 下一步」体验导入文本、AI 设置、整理段落、选词与双语释义、翻页与保存；末步点击「完成演示」关闭。
- 只模拟顶栏以下的主要操作与 AI 设置，不加载完整阅读页。可以编辑短示例、试用默认释义语言、点击批注切换中英文，以及更换示例纸张和字号。
- 手册内不提供界面语言按钮，文案跟随首页外部的中英文切换；同源页面的语言更新也会同步，不重置当前步骤、示例输入或模拟操作。支持 Esc / 遮罩 / 关闭按钮，关闭后焦点回到入口，重新打开从第一步重新练习。
- 每步仅展示模拟操作区，不再显示单独的步骤标题与介绍。弹窗固定为 680px 高（小屏不超过视口安全高度），中间演示区独立滚动，切换步骤、显示反馈或中英文变化不会改变窗口高度，上下步按钮始终可见。
- 所有演示状态仅在内存中，不调用 AI、保存文章或写入真实设置；演示密钥只读，无需输入真实密钥。实现位于 `public/ts/manual.ts`、`public/css/manual.css`，复用站点配色与胶带按钮。

### 统一进度条（后续界面约定）
- 所有进度条统一复用 `public/css/progress.css` 的透明胶带样式，来源是 AI 为文章起标题时的逐步贴胶带与翘起前缘；首页手册和阅读页起标题已共用此实现。该约定也记录在 `AGENTS.md`，后续不另建普通细线填充条。
- 结构为 `.tape-progress` → `.tape-progress-track` → `.tape-progress-reveal` → `.tape.tape-progress-strip`；默认保留起标题的 3.4 秒循环，用于无法预知耗时的任务，不伪造完成百分比。
- 已知进度在外层设置 `data-progress="determinate"` 和 `--progress: 40%`，以相同胶带显示实际完成度；同时为进度轨道提供 `role="progressbar"`、可访问名称及 `aria-valuemin / aria-valuemax / aria-valuenow`。手册按当前步数更新胶带长度。
- 减少动态效果时去掉循环和过渡，保留静态胶带及文字；强制颜色模式下使用系统高亮色。

### 1. 文本粘贴与段落展示
- 无正文时点击「Paste text」打开统一编辑区，再按 Ctrl/Cmd+V，点击「Reflow & start reading」完成导入。不会调用 `navigator.clipboard`。
- 有正文时同一按钮改为「Edit page」，可直接修改或粘贴到当前页，改动即时应用，保留当前文章身份；不会因为编辑中的粘贴而误新建文章。
- 导入保留正文中的数字、标点和 Unicode 字符，不静默丢弃内容；英文释义功能仍只解释英文单词。
- 页面将文本按**正确段落**展示：
  - 以空行作为段落分隔符；
  - 段内连续换行合并为单行；
  - 每段渲染为独立的 `<p>`（带段间距）。
- 展示区为**只读**展示（不绑定可编辑文本区域），便于单击选词。

### 2. 分页、编辑与 Word 导入
- 每页最多 **3000 个 Unicode 字符**，字母、数字、标点、空格、换行及 `『释义』` 标记全部计入。优先在段落、句子或空白处分页；所有分页拼接后与排版后的正文完全一致，不截断或丢弃分隔符。
- 粘贴/Word 导入后自动分页并从第一页开始阅读，不再跳到末页；可使用上一页、下一页、页码选择管理全部页面。实时编辑仍按光标位置跟随分页。
- 「Read」为只读选词视图；「Edit page」编辑当前页，输入即时写入同一份正文模型，超过上限时自动向后分流，并跟随光标切换到所在页。删除内容后也会重新分页。
- 「Import Word」支持 **.docx，最大 5 MB**；文件在浏览器本地解压、提取正文并合并错误断行、保留段落，再分页。图片、Word 样式不导入；扫描图像、旧 `.doc`、加密或损坏的文件会明确提示，不改动已有正文。旧 `.doc` 请先另存为 `.docx`。
- 整篇正文上限维持 100000 个 UTF-16 单元，与后端存储校验一致。超限会报错，不会截断。
- 顶部分页栏的 Next 右侧提供「Background」按钮，弹出纸张预览窗口，可选择原本、云龙纸、绵纸、大地纸、牛皮纸、莱尼纸、艺术纹理纸、雅纹纸和皮纹纸。选择立即应用于阅读纸面，不改变正文、分页、释义或文章保存状态；纸张纹理由本地 SVG 模拟，不请求外部图片。使用原生单选框支持方向键选择，支持 Esc / 遮罩关闭并恢复焦点。
- 阅读背景以 `er_reading_background` 保存在当前浏览器的 localStorage，刷新及重开页面后恢复；不上传到账户、不写入文章。未知配置回退原本背景，浏览器禁止存储时仍可切换，并提示选择仅在当前页面有效。实现位于 `public/ts/readingBackground.ts`、`readingBackgroundPreference.ts`、`public/css/readingBackground.css` 与 `public/textures/`。

### 导出 Word（.docx）
- 点击阅读工具栏「Export Word / 导出 Word」，在浏览器本地生成并下载整篇文章的 `.docx`，包含全部分页及已有释义，而不只是当前屏幕上的一页。无需登录、保存文章或配置 API key，不请求 AI、不上传内容。
- 每条释义按其**当前显示的语言**导出：中文批注导出中文，英文批注导出英文，同一文档可以混合两种语言；相同英文释义仍按各自批注的选择独立处理。只有英文的旧批注保留英文，未注释的正文原样保留。切换界面语言不会统一改变导出释义的语言。
- 文档为纯白 A4 纸面、黑色文字；不包含阅读背景、纹理、胶带、批注底色或网页工具栏。释义仅以正文内的 `『释义内容』` 展示，保留段落、换行和制表符，由 Word 自然分页，不复制网页的 3000 字符页边界。
- 已选文章使用原标题作为文档标题及文件名；未保存文章默认下载为 `EngNote.docx`，不调用 AI 起名。文件名自动移除不安全字符。空文章或 AI / 导入等任务进行时按钮禁用；失败会给出可重试提示。
- 导出只读取正文和释义显示快照，不改变阅读位置、语言选择、草稿、保存状态、密钥或背景。实现位于 `public/ts/wordExport.ts`（纯 OOXML / ZIP 生成，复用 `fflate`）和 `public/ts/exportWord.ts`（浏览器下载）。

### 3. 保存到数据库（SQLite）
- 点击「**保存**」按钮：
  - **若已选中本人保存的文章** → 打开保存便签，确认后覆盖更新（保留原标题，只更新内容）；他人的文章及无作者的历史文章保存为自己的新副本。
  - **若未选中**（例如刚粘贴/清空的新内容）→ 打开保存便签，输入**标题**新建一篇；新建成功后自动成为选中项。
  - 新文章标题可留空：使用本标签页已设置的 DeepSeek 密钥，根据**整篇文章**概括 1–20 字符的英文标题，成功后保存。请求期间显示透明胶带缓缓贴上的循环动画；开启减少动态效果时改为静态胶带和文字状态。
  - 起名与释义调用相同接口和已确认密钥，但标题额外受 **20 个字符（含空格，并非 20 个单词）** 限制。旧实现会把超长标题、前缀等格式判为失败，即使 AI 请求本身成功。现在明确要求短标题 JSON，同时兼容纯文本、引号、常见前缀及 Markdown 包装；结果不合规时最多请求一次更短的标题，不静默截断。
  - 未配置密钥、网络 / 鉴权 / 配额 / 超时失败，或两次 AI 输出仍无效时，停止动画并在便签中说明具体错误，提示用户**手动填写标题**，不生成兜底标题、不写入数据库。连接或鉴权失败不会按格式问题重试；输入标题后可直接保存，无需 AI。
  - 总结期间可取消 / Esc / 点击遮罩关闭便签，立即中止请求并释放操作锁；迟到结果不会保存或影响下一次任务。已经发送的数据库写入不会因关闭便签而假装回滚。
- 空白文章首次导入、Word 导入或清空会重置文章选中项；正常 Edit page 修改及粘贴不会重置，保存会更新当前选中的本人文章。
- 标题**不允许输入中文**，且**长度限制 20 个字符**；前后端均校验，无效时提示修正，不静默保存错误标题。
- Save article 保存**整篇文章的所有页面和 `『释义』`**，不是仅保存当前可见页；后台继续存储一份完整正文，加载时按相同规则分页，兼容旧数据库。
- 数据写入 **SQLite**（`data.db`），浏览器刷新后仍保留。

### 3. AI 整理（排版）
- 点击「Tidy this page」，仅将当前页发送给 DeepSeek；保留当前页前后的空白分隔，避免与相邻页错误拼词。
- AI 按以下规则输出**正确排版格式**的文本：
  1. 修正错误断行、多余空行；
  2. 统一段落分隔（段落之间一个空行）；
  3. 修正英文标点（`, . ? ! ' "` 等）前后的空格错误；
  4. 保留原文中的事实、数字与单词，不主动改写内容；
  5. 返回纯文本，不包含任何解释性内容。
- 返回结果只替换当前页所对应的正文区间，其余正文保留，随后按 3000 字符上限重新分页。

### 4. AI 翻译（单词注释）
- 点击「AI 翻译」后进入**选词模式**，用户在文本中**单击单词**即可选中，选中的单词会**高亮背景色**（再单击取消，可多选）。
- 选词解析规则：
  - **单个单词**：在该单词后方追加 `『』`，`『』` 内为**纯英文释义**。
    - 例：`apple『a round fruit with red or green skin』`
  - **连续单词（相邻短语）**：视为一个整体，在短语整体后方追加一个 `『』`，解释该短语含义。
    - 例：`take off『to leave the ground and begin to fly』`
  - **不连续的多个单词/词组**：每个被选中的片段**分别**在其后方追加各自的 `『』`，逐个用纯英文解释。
    - 例：`The quick『fast』brown fox jumps over the lazy『slow-moving』dog`
- **AI 释义每批一次请求同时返回英文和对应的中文**，两种语言均通过校验后才插入注释；新释义初始默认显示英文，可在 AI setup 用 **Zh / Eng** 切换后续新释义的默认显示语言。在 **Read** 模式点击胶带释义即刻切换中文，再次点击切回英文，**切换不发送 AI 请求，也不需要 API key**。各条释义互不影响，当前标签页独立记忆每条的显示语言，刷新或从首页返回后保持。
- 中英文内容随文章一并保存，重新打开收藏文章也能直接切换；其他读者首次打开仍默认英文。正文保持 `『英文释义』`，中文以匹配正文偏移的附加数据保存，不影响 3000 字符分页。切换显示语言不会造成“未保存修改”，但新增 / 修改双语释义仍需保存。
- 旧记录如果只有英文且没有缓存中文，点击仅提示使用 Add definitions 重新生成双语释义，不会悄悄请求翻译。重新释义会替换该词的旧注释，不重复叠加；旧文章和旧版草稿继续可读。SQLite 自动新增双语数据列，保留已有正文与作者信息。
- 「Define selected」先保留已有完整双语注释，再复用查询缓存，只请求缺失词条；相同词组在同批去重，一条结果回填多个位置。不把 `US` 与 `us` 等不同大小写的词盲目合并。已有注释保留各自的显示语言，不因复用而重置。
- 查询缓存为通用词典释义，不额外发送全文或上下文；仅把查询词组和双语结果保存在本浏览器的 `er_dictionary_cache_v2`，包含模型 / 提示词版本，最多 256 条、7 天有效，满额淘汰最近最少使用项；刷新及跨文章可复用。存储被禁用时降级为内存，不影响释义或本地切换。AI setup 的「Usage & dictionary cache」可清除查询缓存，不删除文章注释或 API key。
- 「Refresh selected」明确绕过已有释义及缓存，重新请求所选词组（同批仍去重）；用于主动更新，不自动重新生成。新注释随草稿和文章保留可选的 `term` 查询身份，避免把单词释义误当作不同短语的结果。旧双语注释默认保留，但不猜测其来源词组来填充共享查询缓存；只有英文的旧注释仍可正常补全。
- 提示词要求英文最多 20 个单词、中文最多 20 个字符的短释义；客户端仍兼容有效的较长旧结果（每种语言 600 字符技术上限），不静默截断。每批最多 12 个不同词组，并按输入长度分批、动态配置输出预算，使用 JSON object 输出模式和非思考模式。
- 翻译前的选中高亮在翻译完成后清除，由 `『释义』` 标记取代。

**翻译交互流程**（两步：先选词，再点翻译）：
1. 点击「AI 翻译」按钮 → 进入**选词模式**，直接在页面单击选词。
2. 用户在文本中**单击单词**选中并高亮背景色（再单击取消，可多选相邻或不相邻的单词/短语）。
3. 点击独立的「Define selected (数量)」执行释义；锁定冲突编辑和翻页操作，待解释单词显示点状下划线，状态栏展示进度，不往正文插入临时占位字符。
4. API 返回 `{ "definitions": [{ "term", "english", "chinese" }] }`（兼容旧 JSON 数组）；只接受本批请求过的词条，按正文偏移插入 / 更新 `『英文释义』`，同时关联中文并按默认语言显示，然后自动分页；正文中的英文释义计入 3000 字符限制。缺少任一语言或超过技术长度上限的结果不截断、不插入。
5. 成功词条及时进入缓存；部分失败时仍应用有效结果，之后只需选择缺失词重试。若接口明确返回 `finish_reason=length`，只恢复已完整闭合且校验通过的 JSON 词条，不猜测被截断内容；失败后不自动重试或继续发送后续批次。取消后的迟到结果不会写入正文或缓存。
6. Add definitions 进入模式后仍显示原名称，不改成 Cancel，也不新增取消按钮；重复点击不会退出或清除选词。点击 Read 或按 Esc 恢复普通阅读，清除选词/删除注释的临时状态，但保留已有释义。
7. 释义请求进行中仍可点击 Read 或按 Esc：中止浏览器请求并释放操作锁，迟到结果不会写入正文，旧请求也不会解锁或重置之后发起的新任务。
8. Read 模式支持鼠标点击以及 Tab + Enter / Space 本地切换中英文，无额外加载等待。选词模式点击旧释义不会切换语言；删除模式仍为两次点击删除，并同步移除对应中文数据。编辑导致注释偏移时跟踪原注释；取消 AI 释义后迟到的中英文结果都不会写回。
9. 释义注释使用半透明、带细微反光与撕边的胶带背景；长注释按行续贴，不剪裁文字或焦点轮廓。删除选中时胶带变为浅玫瑰色并显示虚线轮廓，正文和保存格式保持不变。

### 5. 删除翻译（删除按钮）
- 点击「**删除翻译**」按钮进入删除模式（按钮变红）。
- **单击一个 `『』` 译文** → 选中（红色高亮）。
- **再次单击同一个 `『』`** → 删除该条翻译，恢复纯原文。
- 再次点击「删除翻译」按钮退出删除模式。

### 6. 收藏白板（已保存文章）
- 点击顶栏「Saved articles」打开略微倾斜的白色收藏板，桌面最大宽度 1080px，两侧胶带固定在白板边框上；关闭后正文仍占满阅读区。
- 文章在带淡灰色网格的二维画布中排布，不产生上下滚动列表；鼠标 / 单指拖动平移，滚轮 / 双指捏合缩放，网格、文章胶带及删除按钮同步移动和缩放。网格仅作背景装饰，不拦截点击，强制颜色模式下隐藏。拖动结束不会误触打开或删除。
- 缩放范围仍限制为 **25%–200%**，但不显示左下角调节器、范围文字或操作说明；仅在右下角保留 Fit all 和 Reset 100%。当前缩放状态供屏幕阅读器播报，不占用视觉区域。首次打开会适配现有文章；列表刷新和重新打开白板保留本次页面内的视角。
- 画布聚焦后可用方向键移动、`+` / `−` 缩放、`0` 复位、`F` 适配全部。键盘聚焦屏幕外文章时会将其移入可见区域，不依赖滚动条。
- 所有公开文章以紧凑的半透明胶带按钮展示标题与日期，长标题自动换行，当前文章用下划线和勾号标记。
- 点击标题加载整篇文章（含 `『』` 释义），成功后关闭白板。若有未保存更改，确认便签叠放在白板上，取消时保留白板与草稿。
- 作者文章的胶带右上角有「×」删除按钮，确认后删除所有保存页面；白板保持打开并修复键盘焦点。若删除的是当前文章则取消选中，阅读区正文保留。
- 「↻ 刷新」重新拉取列表；其他作者的文章和无作者的历史文章没有删除按钮。

### 7. DeepSeek API 接入
- API 地址：`https://api.deepseek.com/chat/completions`（OpenAI 兼容）。
- 模型：`deepseek-chat`。
- 请求头：`Authorization: Bearer <API_KEY>`。
- API 设置便签中的 **Zh / Eng** 按钮切换新 AI 释义默认显示中文还是英文，下划线标记当前选择，点击立即生效，不需要 API key、不会发送请求，也不会确认尚未保存的密钥草稿。仅影响之后生成的释义，不重置已有注释的独立显示状态。偏好单独保存在当前浏览器的 localStorage，刷新 / 再次打开后保留；存储被禁用时提示并在当前页面继续生效，不改动 API key 的标签页存储策略。
- 点击「AI setup」打开便签，在手写横线上输入 API Key，选择「Keep for this tab」后才应用并**保留到当前标签页**（`sessionStorage`）；刷新可恢复，关闭标签页后清除。关闭弹出便签（关闭按钮、遮罩或 Esc）会丢弃未确认的密钥草稿，继续使用原来的密钥。
- 未配置密钥时使用排版 / 释义功能会打开设置便签；留空标题保存则在保存便签内提示手动输入标题，不打断保存流程。设置本身不发送 AI 请求。Show key、Forget key 和 Keep for this tab 共用一行，保持设置便签紧凑；可显示/隐藏密钥，或点击「Forget key」立即清除。浏览器禁止存储时会明确提示，已确认的密钥仍可用于当前页面。
- 不使用 Cookie，不随本地 API 请求传输；`aiSettings.ts` 将设置草稿与实际请求所用的密钥分开管理。
- API Key 仅存在浏览器端，**不上传**到我们的服务器/数据库。
- 请求失败（超时、鉴权失败）时页面给出明确错误提示。释义缓存 / 已有完整注释命中时不需要 API key；只有缺失词条或主动 Refresh selected 才请求 AI。
- AI setup 的「Usage & dictionary cache」显示当前标签页的请求次数、接口实际报告的输入 / 输出 token 和服务端缓存命中 token；统计以 `er_ai_usage_v1` 存在 sessionStorage，不记录密钥、提示词或正文。未返回 usage、失败或中止的请求明确标为用量未知，不当作零消费，不推算账单金额。所有 AI 任务均计入；释义按词数动态预算，标题限制 128 输出 token，当前页排版单独预算，避免全局小预算截断长正文。
- JSON 模式与参数依据 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode) 和 [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion)；保留现有 `deepseek-chat` 模型配置，不自动切换模型或增加付费重试。

### 8. 邮箱注册 / 登录
- 点击顶栏 Login 打开账号便签纸弹窗，在窗口内选择登录或注册；校验错误直接显示在便签内，正文、当前页和未保存的编辑不受影响。
- **注册**需邮箱 + 验证码 + 密码（≥6 位）：
  - 点击「Send Code」→ 后端生成 6 位验证码，存 **Redis**（TTL 5 分钟），并通过 **SMTP**（`.env` 配置）发送到邮箱。
  - 验证码邮件采用与账号弹窗一致的水灰背景、米白便签与鼠尾草绿胶带；中文文案突出可复制的完整六位验证码、实际有效期及安全提醒。使用内联样式与自适应表格兼容手机邮箱，同时提供内容一致的纯文本版本；不依赖外部图片、字体或网页 CSS。模板位于 `backend/verificationEmail.ts`，不涉及手机短信。
  - 验证码正确且邮箱未注册才算注册成功。
- **登录**：邮箱 + 密码 → 校验通过后签发会话，**服务端 Redis / 开发内存 TTL 与 Cookie Max-Age 统一为 24 小时（86400 秒）**，通过 HttpOnly / SameSite Cookie 传递，前端启动时向 `/api/auth/me` 校验。到期后需重新登录，不因访问页面而续期；旧版本已签发的会话需重新登录才能应用新期限。
- 登录界面**无需验证码**（验证码只在注册时要求）。
- 登录后顶栏按钮显示 Account；弹出便签内显示当前邮箱和 Logout，退出后恢复登录表单，顶栏切回 Login。
- **未登录用户**可使用粘贴、AI 整理、翻译等功能，但**不能保存/覆盖/删除文章**（前端阻止并提示「Please log in to save」，后端接口也会校验登录态返回 401）。
- 密码使用**慢哈希算法（Argon2id）**加密后存 SQLite，绝不存明文。
- 会话 Cookie 由浏览器自动携带，前端不可读取 Token；写请求校验同源，文章写操作校验作者。

## 文本格式输出逻辑（核心设计）

```
原始文本
   │  按 \n\n（空行）分段
   ▼
段落数组 paragraphs: string[]
   │  每段内部：合并多余换行、整理空格与标点
   ▼
清洗后的段落数组
   │  渲染为 <p> 列表（每段独立块，段间距分隔）
   ▼
页面展示
   │  AI 整理：当前页文本 → DeepSeek → 替换正文对应区间 → 重新分页
   │  AI 释义：选中片段 → 解析分组 → 成功后按正文偏移插入 『释义』 → 重新分页
   ▼
更新后的段落数组 → 重新渲染
```

### 数据结构

```ts
// 原始输入
rawText: string;

// 按空行切分后的段落
paragraphs: string[];

// 渲染节点：一段文本 + 可选的注释标记
interface Segment {
  text: string;        // 单词/短语原文
  note?: string;       // 『』内的英文释义（未选中时为 undefined）
}
interface Paragraph {
  segments: Segment[]; // 按出现顺序排列，未选中部分 text 即为整句
}

// 选中翻译分组结果
type SelectionGroup = {
  start: number;       // 在段落中的起始偏移
  end: number;         // 结束偏移
  isContiguous: boolean; // 是否连续
};
```

### 选词分组算法
1. 用户**单击**单词 → 加入选中集（高亮背景，再次单击取消）。
2. 按单词 id（文档顺序）排序 → 得到有序选中列表 `pickedIds`。
3. id 相邻、在同一段落且中间只有空白时，合并为一个词组；不跨标点、注释或段落合并。
4. 不相邻的单词各自成组 → 各自一个 `『』`。
5. 确定分组后，记录末尾单词的正文偏移并在状态栏显示进度。
6. 先复用已有双语注释与查询缓存，对缺失词组去重、分批发送 DeepSeek，每批返回 `{ "definitions": [{ "term", "english", "chinese" }] }`；按原始目标偏移回填同词的不同位置。
7. 按正文偏移从后向前插入 `『meaning』`，统一重新分页和渲染。

## API 约定

### POST /chat/completions（DeepSeek）

```json
{
  "model": "deepseek-chat",
  "messages": [
    {
      "role": "system",
      "content": "You are a text formatting assistant. 只输出整理后的纯英文文本，不添加任何说明。"
    },
    {
      "role": "user",
      "content": "<待整理的英文原文>"
    }
  ],
  "temperature": 0.3,
  "thinking": { "type": "disabled" },
  "stream": false,
  "max_tokens": 2048
}
```

- **AI 整理**：system 提示词约束输出为规范排版的纯文本，预算随当前页长度变化。
- **AI 释义**：只发送去重后的词表，返回短双语 JSON 对象，追加 `response_format: { "type": "json_object" }`；预算为 `min(4096, 160 + 128 × 词条数 + ceil(词组总字符数 / 2))`。读取 `finish_reason` 与 `usage`，不靠降低 temperature 或开启流式来宣称节省 token。
- **AI 标题**：保留整篇文章总结及原有格式修正流程，单次输出预算 128 token，使用 JSON object 模式。

## 本地 REST API（Bun + SQLite）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/entries` | 列出已保存文章（id, title, created_at） |
| POST | `/api/entries` | 保存文章，JSON `{ title, content, definitions? }`，双语数据与正文同时写入 |
| PUT | `/api/entries/:id` | 更新正文与双语数据（保留原标题），JSON `{ content, definitions? }` |
| GET | `/api/entries/:id` | 获取单篇文章（含 content、definitions，显示语言默认英文） |
| DELETE | `/api/entries/:id` | 删除一篇文章 |

保存请求示例：

```json
{
  "title": "My Reading",
  "content": "The quick brown fox『fast』jumps over..."
}
```

- `content` 保存完整正文（包含全部分页及 `『』` 释义），并保留页面边界的空白字符。
- 文章表：`entries(id, title, content, created_at, owner_email, definitions)`，存储于 `data.db`；`definitions` 为匹配正文注释的双语 JSON 数组（`start, english, chinese`，服务端规范化为英文显示；可选的 `term` 保存生成时的查询词组，用于缓存复用和 Refresh selected，旧数据没有该字段仍可正常读取）。旧表无损追加该列，默认为 `[]`；历史记录作者为空且只读。

### 认证 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/send-code` | 生成验证码存 Redis 并发送到邮箱，`{ email }` |
| POST | `/api/auth/register` | 邮箱注册，`{ email, password, code }` |
| POST | `/api/auth/login` | 登录，`{ email, password }` → HttpOnly 会话 Cookie |
| POST | `/api/auth/logout` | 注销当前 Cookie 会话 |
| GET | `/api/auth/me` | 校验当前 Cookie 会话 |

- 密码存入 SQLite 时经 **Argon2id 慢哈希**（`Bun.password`）。
- 验证码与会话 Token 存 **Redis**（`auth:code:<email>` / `auth:token:<token>`）；Redis 不可用时降级为内存（仅开发）。
- 文章**写操作**需有效会话；未登录 `401`，修改非本人文章 `403`；`GET` 列表/读取公开，仅返回 `can_edit` 权限标记，不泄露作者邮箱。

首页（`/`）为手账欢迎页，点击「Start a new page」进入阅读页（`/index.html`）。

两页均支持手机自适应；阅读页通过 `public/css/reader.css` 按固定顺序导入样式，避免开发热更新时级联顺序不一致。

### 部署到服务器（域名 / 直接链接）
- 端口：未设置 `PORT` 时，本地 `bun dev` 默认 **3000**，生产 `bun start` 默认 **80**。因此远程直接运行 `bun start` 后访问 `http://服务器地址/` 即可，不必带端口；本地开发仍访问 `http://localhost:3000`。如需固定端口，在 `.env` 设置 `PORT=...` 会覆盖默认值。
- 直接监听 80 需要绑定特权端口权限。可用 root / systemd 服务运行，或为 Bun 添加能力：`sudo setcap 'cap_net_bind_service=+ep' "$(command -v bun)"`；也可以让 Nginx 监听 80/443，并把本服务改回 `PORT=3000` 反向代理。
- `HOST` 默认 `0.0.0.0`，允许远程及局域网访问；若仅供本机或本机反向代理使用，可设 `HOST=127.0.0.1`。使用 Nginx 等反向代理时保留请求 Host，并将 `APP_ORIGIN=https://你的域名` 设为公开源地址；使用 HTTPS 时设置 `COOKIE_SECURE=true`。
- 远程 `.env` 必须使用生产配置：配置正确的 SMTP 与 Redis，不要沿用本地含 `PORT=3000` 的端口设置（删除 `PORT` 或改为 80）。`bun start` 直接运行源码，生产模式不返回开发验证码，Redis 不可用时认证失败而不静默降级。生产启动前请备份 `data.db`，不要执行测试账号 seed。
- 直接使用 HTTP 80 时保持 `COOKIE_SECURE` 未开启；配置 HTTPS 后再设为 `true`，否则浏览器不会回传会话 Cookie。
