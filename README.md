# EngNote 英文阅读助手

一个基于 **HTML + TypeScript + CSS** 的英文阅读网页应用。用户通过单一「Paste text / Edit page」入口粘贴、编辑正文或导入 Word，正文重新排版后按每页最多 3000 字符展示；支持调用 DeepSeek API 进行「AI 整理」排版与「AI 翻译」单词注释；可将内容**保存到 SQLite 数据库**并通过顶栏的收藏白板读取，保存时可留空标题由 AI 概括；支持**邮箱注册/登录**（带验证码）。

![](./home.png)

## 快速启动（源码脚本模式）

```bash
cd EngNote
bun install --frozen-lockfile
cp .env.example .env   # 已有 .env 请保留，不要覆盖
bun dev
```

打开 `http://localhost:3000`。已验证 Bun **1.3.14**。无需编译可执行文件，也不再依赖 `public/dist/app.js`：Bun 原生 HTML 入口负责前端 TS / CSS 打包与开发热更新，服务端修改由 `--watch` 重启。

- `bun start`：生产模式直接运行源码（关闭 HMR），仍需保留源码、依赖与静态资源；生产认证需要 Redis、SMTP。
- `bun run typecheck`：分别检查前后端类型；`bun test`：运行文本规则、分页边界、实时编辑、Word 解压限制、接口与数据库迁移测试。
- `bun run build`：可选，仅导出前端到 `dist/` 用于检查，不是可单独部署的完整应用；SQLite / 登录仍需 Bun 后端。
- 默认绑定 `0.0.0.0`，启动时输出本机及局域网地址；同一局域网设备可用 `http://本机局域网IP:3000` 访问（需放行防火墙端口）。如需仅本机访问，设 `HOST=127.0.0.1`。粘贴统一使用页内输入区和 Ctrl/Cmd+V，不请求剪贴板权限，也不会由 Paste 按钮触发浏览器“粘贴（P）”菜单。
- 原 `Engreading` / `index.js.map` 不再使用，也不会自动删除；现有 `.env` 与 `data.db` 保留。

### 代码逻辑与本次调整

`index.ts` 管理启动和退出 → `backend/server.ts` 初始化 SQLite、挂载两页 HTML、校验 API → `backend/auth.ts` / `redis.ts` / `mail.ts` 处理登录、验证码和会话。前端 `main.ts` 装配事件，`state.ts` 管理段落与选词，`db.ts` 管理保存/列表，`format.ts` 与 `translate.ts` 调用 DeepSeek。新增 `pagination.ts` 管理无损正文与分页，`editor.ts` 处理导入、实时编辑和草稿，`panels.ts` 管理文章内面板，`notes.ts` 管理保存 / 收藏 / 确认 / API / 账号弹窗的叠放、焦点与关闭行为，`articleTitle.ts` 管理 AI 标题总结、格式兼容与一次短标题修正，`collectionCanvas.ts` / `boardGeometry.ts` 管理收藏画布与可测试的缩放几何，`word.ts` 在浏览器提取 Word 正文。

- 修复全局正则反复校验不稳定、粘贴丢失数字、标点也被选中、跨段落合并短语等问题。
- AI 期间锁定冲突操作，使用页面版本及请求序号防止过期结果覆盖新内容；加载/失败标记不写入文章。先排版后注释，避免 AI 排版移动已有释义。
- 仅导入与编辑保留页内面板；保存、删除、未保存确认、收藏、AI 设置和账号使用原生 `<dialog>` 浮层，不替换正文或编辑区。收藏白板支持叠放确认便签；弹窗支持点击遮罩和 Esc，Tab 在当前弹窗内循环，关闭后恢复原焦点及编辑光标；不使用 `window.confirm` 或离页原生确认。
- 工作草稿自动保存在当前标签页的 sessionStorage，刷新会恢复全部分页，作为未保存文章避免误覆盖原记录；永久保存仍需登录后使用 Save article。浏览器禁止存储时会提示，关闭标签页会失去临时草稿。
- 会话改为 HttpOnly / SameSite Cookie，不再在 localStorage 保存 Token；API Key 从 Cookie 迁移为当前标签页的 sessionStorage，并可随时清除。
- 文章仍是**公开阅读书架**，不是私密笔记；只有作者可更新/删除。旧表自动追加 `owner_email`，历史文章不猜测作者，保留公开只读，可另存为自己的副本。API 不公开作者邮箱。
- 静态资源通过 HTML 入口与明确白名单提供，不再拼接任意文件路径；接口校验 JSON 类型、长度、方法与请求来源。
- 首页三张胶带便签，阅读页为笔记纸；`public/css/tokens.css` 统一水灰中性色，`public/css/tape.css` 提供不同颜色、半透明撕边的胶带按钮。按钮装饰与焦点轮廓分离，键盘和触摸操作不受剪裁影响。
- 首页与阅读页的顶栏、主区域均使用全宽布局，仅保留响应式边距；首页标题为 “Use English exclusively”，以英文释义和上下文理解英文，不再保留首页页尾；阅读页移除宣传大标题，直接显示工具栏与文章。
- 顶栏保留 Logo、Saved articles、AI setup 和 Login / Account；正文独占全部可用宽度，不再保留收藏侧栏。Saved articles 打开微倾斜白板，保留两侧粘住白板的胶带，不恢复线稿或装饰文案；文章为紧凑的透明胶带按钮，作者的删除按钮位于胶带右上角。白板采用可拖动、缩放的二维画布，文章再多也不产生上下滚动的列表。密钥输入区保留 SVG 铅笔横线与手写风排版。
- 文章工具固定两行：第一行 Read、Paste text / Edit page、Import Word、Tidy this page；第二行 Add definitions、Remove a note、Save article、Clear。Read 紧挨编辑按钮左侧，不再有单独的阅读标签行；选词时执行释义按钮加入第一行，仍保持两行。
- 取消重复的 Add text / Edit page 标签和两枚独立工具按钮，只保留一个正文入口：无正文时显示 Paste text，有正文时显示 Edit page，共用一个文本编辑区。
- `public/icons/reading-sketch.svg` 与 `pencil-line.svg` 均为本地线稿，无外部字体或 UI 框架。

## 功能需求

### 1. 文本粘贴与段落展示
- 无正文时点击「Paste text」打开统一编辑区，再按 Ctrl/Cmd+V，点击「Reflow & start reading」完成导入。不会调用 `navigator.clipboard`。
- 有正文时同一按钮改为「Edit page」，可直接修改或粘贴到当前页，改动即时应用，保留当前文章身份；不会因为编辑中的粘贴而误新建文章。
- 导入保留正文中的数字、标点和 Unicode 字符，不静默丢弃内容；英文释义功能仍只解释英文单词。
- 页面将文本按**正确段落**展示：
  - 以空行作为段落分隔符；
  - 段内连续换行合并为单行；
  - 每段渲染为独立的 `<p>`（带段间距）。
- 展示区为**只读**展示（不绑定可编辑文本区域），便于单击选词。

### 2. 分页、编辑与 Word 导入
- 每页最多 **3000 个 Unicode 字符**，字母、数字、标点、空格、换行及 `『释义』` 标记全部计入。优先在段落、句子或空白处分页；所有分页拼接后与排版后的正文完全一致，不截断或丢弃分隔符。
- 粘贴/Word 导入后自动分页并定位到末页；可使用上一页、下一页、页码选择管理全部页面。
- 「Read」为只读选词视图；「Edit page」编辑当前页，输入即时写入同一份正文模型，超过上限时自动向后分流，并跟随光标切换到所在页。删除内容后也会重新分页。
- 「Import Word」支持 **.docx，最大 5 MB**；文件在浏览器本地解压、提取正文并合并错误断行、保留段落，再分页。图片、Word 样式不导入；扫描图像、旧 `.doc`、加密或损坏的文件会明确提示，不改动已有正文。旧 `.doc` 请先另存为 `.docx`。
- 整篇正文上限维持 100000 个 UTF-16 单元，与后端存储校验一致。超限会报错，不会截断。

### 3. 保存到数据库（SQLite）
- 点击「**保存**」按钮：
  - **若已选中本人保存的文章** → 打开保存便签，确认后覆盖更新（保留原标题，只更新内容）；他人的文章及无作者的历史文章保存为自己的新副本。
  - **若未选中**（例如刚粘贴/清空的新内容）→ 打开保存便签，输入**标题**新建一篇；新建成功后自动成为选中项。
  - 新文章标题可留空：使用本标签页已设置的 DeepSeek 密钥，根据**整篇文章**概括 1–20 字符的英文标题，成功后保存。请求期间显示透明胶带缓缓贴上的循环动画；开启减少动态效果时改为静态胶带和文字状态。
  - 起名与释义调用相同接口和已确认密钥，但标题额外受 **20 个字符（含空格，并非 20 个单词）** 限制。旧实现会把超长标题、前缀等格式判为失败，即使 AI 请求本身成功。现在明确要求短标题 JSON，同时兼容纯文本、引号、常见前缀及 Markdown 包装；结果不合规时最多请求一次更短的标题，不静默截断。
  - 未配置密钥、网络 / 鉴权 / 配额 / 超时失败，或两次 AI 输出仍无效时，停止动画并在便签中说明具体错误，提示用户**手动填写标题**，不生成兜底标题、不写入数据库。连接或鉴权失败不会按格式问题重试；输入标题后可直接保存，无需 AI。
  - 总结期间可取消 / Esc / 点击遮罩关闭便签，立即中止请求并释放操作锁；迟到结果不会保存或影响下一次任务。已经发送的数据库写入不会因关闭便签而假装回滚。
- 空白文章首次导入、Word 导入或清空会重置文章选中项；正常 Edit page 修改及粘贴不会重置，保存会更新当前选中的本人文章。
- 标题**不允许输入中文**，且**长度限制 20 个字符**；前后端均校验，无效时提示修正，不静默保存错误标题。
- Save article 保存**整篇文章的所有页面和 `『释义』`**，不是仅保存当前可见页；后台继续存储一份完整正文，加载时按相同规则分页，兼容旧数据库。
- 数据写入 **SQLite**（`data.db`），浏览器刷新后仍保留。

### 3. AI 整理（排版）
- 点击「Tidy this page」，仅将当前页发送给 DeepSeek；保留当前页前后的空白分隔，避免与相邻页错误拼词。
- AI 按以下规则输出**正确排版格式**的文本：
  1. 修正错误断行、多余空行；
  2. 统一段落分隔（段落之间一个空行）；
  3. 修正英文标点（`, . ? ! ' "` 等）前后的空格错误；
  4. 保留原文中的事实、数字与单词，不主动改写内容；
  5. 返回纯文本，不包含任何解释性内容。
- 返回结果只替换当前页所对应的正文区间，其余正文保留，随后按 3000 字符上限重新分页。

### 4. AI 翻译（单词注释）
- 点击「AI 翻译」后进入**选词模式**，用户在文本中**单击单词**即可选中，选中的单词会**高亮背景色**（再单击取消，可多选）。
- 选词解析规则：
  - **单个单词**：在该单词后方追加 `『』`，`『』` 内为**纯英文释义**。
    - 例：`apple『a round fruit with red or green skin』`
  - **连续单词（相邻短语）**：视为一个整体，在短语整体后方追加一个 `『』`，解释该短语含义。
    - 例：`take off『to leave the ground and begin to fly』`
  - **不连续的多个单词/词组**：每个被选中的片段**分别**在其后方追加各自的 `『』`，逐个用纯英文解释。
    - 例：`The quick『fast』brown fox jumps over the lazy『slow-moving』dog`
- `『』` 中的解释**仅使用英文**，不用中文，便于沉浸式阅读。
- 翻译前的选中高亮在翻译完成后清除，由 `『释义』` 标记取代。

**翻译交互流程**（两步：先选词，再点翻译）：
1. 点击「AI 翻译」按钮 → 进入**选词模式**，直接在页面单击选词。
2. 用户在文本中**单击单词**选中并高亮背景色（再单击取消，可多选相邻或不相邻的单词/短语）。
3. 点击独立的「Define selected (数量)」执行释义；锁定冲突编辑和翻页操作，待解释单词显示点状下划线，状态栏展示进度，不往正文插入临时占位字符。
4. API 返回后按正文偏移插入 `『纯英文释义』`，然后自动分页；释义也计入 3000 字符限制。
5. 未返回的词可重新选择重试；整个请求失败时正文保持原样。
6. Add definitions 进入模式后仍显示原名称，不改成 Cancel，也不新增取消按钮；重复点击不会退出或清除选词。点击 Read 或按 Esc 恢复普通阅读，清除选词/删除注释的临时状态，但保留已有释义。
7. 释义请求进行中仍可点击 Read 或按 Esc：中止浏览器请求并释放操作锁，迟到结果不会写入正文，旧请求也不会解锁或重置之后发起的新任务。
8. 释义注释使用半透明、带细微反光与撕边的胶带背景；长注释按行续贴，不剪裁文字或焦点轮廓。删除选中时胶带变为浅玫瑰色并显示虚线轮廓，正文和保存格式保持不变。

### 5. 删除翻译（删除按钮）
- 点击「**删除翻译**」按钮进入删除模式（按钮变红）。
- **单击一个 `『』` 译文** → 选中（红色高亮）。
- **再次单击同一个 `『』`** → 删除该条翻译，恢复纯原文。
- 再次点击「删除翻译」按钮退出删除模式。

### 6. 收藏白板（已保存文章）
- 点击顶栏「Saved articles」打开略微倾斜的白色收藏板，桌面最大宽度 1080px，两侧胶带固定在白板边框上；关闭后正文仍占满阅读区。
- 文章在二维画布中排布，不产生上下滚动列表；鼠标 / 单指拖动平移，滚轮 / 双指捏合缩放，文章胶带及删除按钮一起缩放。拖动结束不会误触打开或删除。
- 缩放范围 **25%–200%**，固定控件显示当前比例、最小 / 最大值及到达边界的状态，并提供滑条、加减、Fit all 和 Reset 100%。首次打开会适配现有文章；列表刷新和重新打开白板保留本次页面内的视角。
- 画布聚焦后可用方向键移动、`+` / `−` 缩放、`0` 复位、`F` 适配全部。键盘聚焦屏幕外文章时会将其移入可见区域，不依赖滚动条。
- 所有公开文章以紧凑的半透明胶带按钮展示标题与日期，长标题自动换行，当前文章用下划线和勾号标记。
- 点击标题加载整篇文章（含 `『』` 释义），成功后关闭白板。若有未保存更改，确认便签叠放在白板上，取消时保留白板与草稿。
- 作者文章的胶带右上角有「×」删除按钮，确认后删除所有保存页面；白板保持打开并修复键盘焦点。若删除的是当前文章则取消选中，阅读区正文保留。
- 「↻ 刷新」重新拉取列表；其他作者的文章和无作者的历史文章没有删除按钮。

### 7. DeepSeek API 接入
- API 地址：`https://api.deepseek.com/chat/completions`（OpenAI 兼容）。
- 模型：`deepseek-chat`。
- 请求头：`Authorization: Bearer <API_KEY>`。
- 点击「AI setup」打开便签，在手写横线上输入 API Key，选择「Keep for this tab」后才应用并**保留到当前标签页**（`sessionStorage`）；刷新可恢复，关闭标签页后清除。关闭弹出便签（关闭按钮、遮罩或 Esc）会丢弃未确认的密钥草稿，继续使用原来的密钥。
- 未配置密钥时使用排版 / 释义功能会打开设置便签；留空标题保存则在保存便签内提示手动输入标题，不打断保存流程。设置本身不发送 AI 请求。可显示/隐藏密钥，或点击「Forget key」立即清除。浏览器禁止存储时会明确提示，已确认的密钥仍可用于当前页面。
- 不使用 Cookie，不随本地 API 请求传输；`aiSettings.ts` 将设置草稿与实际请求所用的密钥分开管理。
- API Key 仅存在浏览器端，**不上传**到我们的服务器/数据库。
- 请求失败（超时、鉴权失败）时页面给出明确错误提示。

### 8. 邮箱注册 / 登录
- 点击顶栏 Login 打开账号便签纸弹窗，在窗口内选择登录或注册；校验错误直接显示在便签内，正文、当前页和未保存的编辑不受影响。
- **注册**需邮箱 + 验证码 + 密码（≥6 位）：
  - 点击「Send Code」→ 后端生成 6 位验证码，存 **Redis**（TTL 5 分钟），并通过 **SMTP**（`.env` 配置）发送到邮箱。
  - 验证码正确且邮箱未注册才算注册成功。
- **登录**：邮箱 + 密码 → 校验通过后签发会话，**服务端 Redis / 开发内存 TTL 与 Cookie Max-Age 统一为 24 小时（86400 秒）**，通过 HttpOnly / SameSite Cookie 传递，前端启动时向 `/api/auth/me` 校验。到期后需重新登录，不因访问页面而续期；旧版本已签发的会话需重新登录才能应用新期限。
- 登录界面**无需验证码**（验证码只在注册时要求）。
- 登录后顶栏按钮显示 Account；弹出便签内显示当前邮箱和 Logout，退出后恢复登录表单，顶栏切回 Login。
- **未登录用户**可使用粘贴、AI 整理、翻译等功能，但**不能保存/覆盖/删除文章**（前端阻止并提示「Please log in to save」，后端接口也会校验登录态返回 401）。
- 密码使用**慢哈希算法（Argon2id）**加密后存 SQLite，绝不存明文。
- 会话 Cookie 由浏览器自动携带，前端不可读取 Token；写请求校验同源，文章写操作校验作者。

## 文本格式输出逻辑（核心设计）

```
原始文本
   │  按 \n\n（空行）分段
   ▼
段落数组 paragraphs: string[]
   │  每段内部：合并多余换行、整理空格与标点
   ▼
清洗后的段落数组
   │  渲染为 <p> 列表（每段独立块，段间距分隔）
   ▼
页面展示
   │  AI 整理：当前页文本 → DeepSeek → 替换正文对应区间 → 重新分页
   │  AI 释义：选中片段 → 解析分组 → 成功后按正文偏移插入 『释义』 → 重新分页
   ▼
更新后的段落数组 → 重新渲染
```

### 数据结构

```ts
// 原始输入
rawText: string;

// 按空行切分后的段落
paragraphs: string[];

// 渲染节点：一段文本 + 可选的注释标记
interface Segment {
  text: string;        // 单词/短语原文
  note?: string;       // 『』内的英文释义（未选中时为 undefined）
}
interface Paragraph {
  segments: Segment[]; // 按出现顺序排列，未选中部分 text 即为整句
}

// 选中翻译分组结果
type SelectionGroup = {
  start: number;       // 在段落中的起始偏移
  end: number;         // 结束偏移
  isContiguous: boolean; // 是否连续
};
```

### 选词分组算法
1. 用户**单击**单词 → 加入选中集（高亮背景，再次单击取消）。
2. 按单词 id（文档顺序）排序 → 得到有序选中列表 `pickedIds`。
3. id 相邻、在同一段落且中间只有空白时，合并为一个词组；不跨标点、注释或段落合并。
4. 不相邻的单词各自成组 → 各自一个 `『』`。
5. 确定分组后，记录末尾单词的正文偏移并在状态栏显示进度。
6. 将分组发送 DeepSeek，一次请求返回每组的纯英文释义数组（`[{word, meaning}]`）。
7. 按正文偏移从后向前插入 `『meaning』`，统一重新分页和渲染。

## 本地 REST API（Bun + SQLite）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/entries` | 列出已保存文章（id, title, created_at） |
| POST | `/api/entries` | 保存文章，JSON `{ title, content }` |
| PUT | `/api/entries/:id` | 覆盖更新文章内容（保留原标题） |
| GET | `/api/entries/:id` | 获取单篇文章（含 content） |
| DELETE | `/api/entries/:id` | 删除一篇文章 |

保存请求示例：

```json
{
  "title": "My Reading",
  "content": "The quick brown fox『fast』jumps over..."
}
```

- `content` 保存完整正文（包含全部分页及 `『』` 释义），并保留页面边界的空白字符。
- 文章表：`entries(id, title, content, created_at, owner_email)`，存储于 `data.db`；旧表无损迁移，历史记录作者为空且只读。

### 认证 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/send-code` | 生成验证码存 Redis 并发送到邮箱，`{ email }` |
| POST | `/api/auth/register` | 邮箱注册，`{ email, password, code }` |
| POST | `/api/auth/login` | 登录，`{ email, password }` → HttpOnly 会话 Cookie |
| POST | `/api/auth/logout` | 注销当前 Cookie 会话 |
| GET | `/api/auth/me` | 校验当前 Cookie 会话 |

- 密码存入 SQLite 时经 **Argon2id 慢哈希**（`Bun.password`）。
- 验证码与会话 Token 存 **Redis**（`auth:code:<email>` / `auth:token:<token>`）；Redis 不可用时降级为内存（仅开发）。
- 文章**写操作**需有效会话；未登录 `401`，修改非本人文章 `403`；`GET` 列表/读取公开，仅返回 `can_edit` 权限标记，不泄露作者邮箱。

### 部署到服务器（域名）
- `PORT` 默认 3000，`HOST` 默认 `0.0.0.0`，允许局域网访问；保留显式 `HOST` 配置，若仅供本机或本机反向代理使用，可设 `HOST=127.0.0.1`。可用 Nginx 反向代理到本服务，保留请求 Host，并将 `APP_ORIGIN=https://你的域名` 设为公开源地址。使用 HTTPS 并设置 `COOKIE_SECURE=true`。
- `bun start` 直接运行源码；配置正确的 SMTP 与 Redis。生产模式不返回开发验证码，Redis 不可用时认证失败而不静默降级。生产启动前请备份 `data.db`，不要执行测试账号 seed。
